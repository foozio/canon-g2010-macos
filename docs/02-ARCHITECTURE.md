# 02 — Architecture of the working solution

## Design constraints discovered along the way

| Constraint | Consequence |
|---|---|
| Apple's `cupsd` sandbox only executes filters from its ServerBin or `/Library/Printers/**` — both root-owned | A user-built filter cannot be a *system* queue's filter |
| Any queue whose filter is user-owned triggers the print system's **"insecure permissions"** flag | Same conclusion, plus visible warnings in Printer settings |
| `/usr/sbin/cupsd` is `-r-x------ root wheel`; Homebrew's `cups` formula ships libraries + tools but **no daemon** | Cannot run a second full cupsd as the user |
| Canon's driver deadlocks on Tahoe (see [01-DIAGNOSIS.md](01-DIAGNOSIS.md)) | Must not touch the Canon filter chain at all |

## Chosen design: standalone IPP server in userspace

```
                    macOS (user: foozio — no sudo anywhere)
┌─────────────────────────────────────────────────────────────────┐
│ App / lp                                                        │
│   ▼                                                             │
│ System queue "G2010IPP"  (driverless, -m everywhere)            │
│   uri = ipp://localhost:8632/ipp/print                          │
│   ▼                                                             │
│ ippeveprinter  (Homebrew cups 2.4.19)  port 8632                │
│   advertises application/pdf; spools job; runs per-job command  │
│   ▼                                                             │
│ ~/Library/Application Support/G2010PrintServer/print-pipeline.sh│
│   1) /usr/libexec/cups/filter/cgpdftoraster   PDF → CUPS raster │
│   2) ~/gp/cupsexec/filter/rastertogutenprint.5.3                │
│        raster → Canon BJ dialect  (native arm64, Gutenprint     │
│        5.3.3 built from SourceForge git tag gutenprint-5_3_3)   │
│   3) /usr/libexec/cups/backend/usb  (DEVICE_URI env, direct)    │
│        BJ stream → USB bulk endpoints                           │
│   ▼                                                             │
│ Canon PIXMA G2010                                               │
└─────────────────────────────────────────────────────────────────┘
```

Why this shape wins:

- **Apple's own `cgpdftoraster` and `usb` backend are ordinary executables.**
  They don't require cupsd — they accept CUPS calling conventions and
  environment variables (`PPD`, `DEVICE_URI`). We simply call them.
- **Gutenprint speaks enough of Canon's printer language** (`bjc-G2000-series`
  driver, EXPERIMENTAL-but-proven on Linux for years) and has no interest in
  ink-status handshakes: it converts and streams.
- **`ippeveprinter` gives us a real IPP server**, so the macOS print system
  integrates normally (queue appears in Printers & Scanners, default printer,
  per-app dialogs) while every byte of conversion happens in userspace as you.

## Component inventory

| Component | Path | Origin |
|---|---|---|
| IPP server | `/opt/homebrew/opt/cups/bin/ippeveprinter` | brew `cups` (keg-only) |
| Controller | `harness/printserver-control.sh` | installs and atomically resets the runtime |
| Installed launcher | `~/Library/Application Support/G2010PrintServer/start-printserver.sh` | copied from `harness/` |
| Installed pipeline | `~/Library/Application Support/G2010PrintServer/print-pipeline.sh` | copied from `harness/` |
| Raster→Canon filter | `~/gp/cupsexec/filter/rastertogutenprint.5.3` | built from source ([06-BUILD-NOTES.md](06-BUILD-NOTES.md)) |
| Libraries/data | `~/gp/lib`, `~/gp/share` | same build |
| PPD | `G2010_gutenprint/stp-bjc-G2000-series.5.3.ppd` | generated by `cups-genppd.5.3`, `*cupsFilter` rewritten to absolute path |
| Scanner backend | brew `sane-backends` (`/opt/homebrew/bin/scanimage`) | pixma driver |
| Persistence | `~/Library/LaunchAgents/com.foozio.g2010.printserver.plist` | launchd is the sole process owner; runtime is outside Downloads |

## Security notes

- Everything runs as your user; no daemons with elevated rights were added.
- The pipeline script hardcodes the local USB URI; nothing listens off-box
  except `127.0.0.1:8632`.
- The old experimental direct-filter queue was deleted precisely because macOS
  flags user-owned filters as insecure — the working route never exposes one to
  the system scheduler.
